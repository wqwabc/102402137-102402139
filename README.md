# 校园失物招领小程序（Web）

---

## 一、项目简介

一个面向校园的轻量级失物招领网页：

**发布信息 → 浏览 / 搜索 → 查看详情 → 联系发布者 → 更新状态（已找到 / 已归还）**

- 发布 **寻物启事**（我丢了东西）或 **失物招领**（我捡到东西），支持物品图标、物品照片、个人联系方式
- 首页集中浏览全部信息，支持按 **物品名称 / 描述 / 地点** 关键词搜索，命中关键词黄色高亮
- **类型（全部/寻物/招领）× 物品分类 × 校园地点** 筛选，可按 **最新 / 最热** 排序，列表分页「加载更多」
- 详情页展示完整信息与物品照片；联系方式默认隐藏，点击后查看并可**一键复制**
- 找回/归还后由 **发布者本人** 标记「已找到 / 已归还」，该信息自动**灰化沉底**，减少重复打扰
- 「我的」页可编辑个人资料（昵称/学院/校区/联系方式/头像），查看自己的发布与完成情况
- **智能配对提醒**：发布时自动推荐可能相关的相反类型信息

## 二、目录结构

```
102402137-102402139/
├── index.html          # 首页：浏览 + 搜索框 + 类型/分类/地点筛选 + 排序 + 加载更多
├── search.html         # 搜索页：关键词搜索 + 热门搜索 + 搜索历史
├── publish.html        # 发布/编辑页：寻物招领表单 + 校验 + 照片/图标 + 发布成功页（含智能配对）
├── detail.html         # 详情页：物品详情 + 联系方式一键复制 + 发布者状态维护/编辑/删除

├── css/
│   └── style.css       # 全部样式（居中手机式应用列，移动端竖屏风格）
├── js/
│   ├── store.js        # 【数据层】localStorage 增删改查、校验、搜索/筛选/排序/分页、
│   │                   #   状态维护、统计、智能配对、个人资料；兼容浏览器与 Node
│   ├── common.js       # 【公共层】HTML 转义、关键词高亮、时间格式化、卡片渲染、
│   │                   #   一键复制、toast、悬浮预览
│   ├── index.js        # 首页逻辑
│   ├── search.js       # 搜索页逻辑
│   ├── publish.js      # 发布/编辑表单逻辑
│   ├── detail.js       # 详情页逻辑
│   └── my.js           # 「我的」页逻辑
├── test/               # 单元测试（不影响网页运行，助教可选择性执行）
│   ├── helpers.js      # 测试辅助：内存 localStorage 桩、构造合法数据的工厂函数
│   ├── store.test.js   # 数据层 Store 测试
│   ├── common.test.js  # 公共函数测试
│   ├── flow.test.js    # 业务主流程集成测试
│   ├── pages.test.js   # 页面静态一致性检查
│   └── dom.flow.test.js# DOM 级集成测试（可选，需 jsdom，未装自动跳过）
├── package.json        # 只有 test 脚本，无运行依赖
└── README.md           # 本文件
```

**组织思路：**

- `js/store.js` 是唯一数据入口，所有页面通过它读写；数据层不碰 DOM，将来换后端只需改这一层。
- `js/common.js` 放跨页面复用的纯函数（转义、高亮、时间、卡片渲染、复制、悬浮预览）。
- 每个页面对应一个同名 `.js`，职责单一：取数据 → 渲染 → 绑事件。
- 脚本都是普通 `<script>`，没有模块化 import，所以 `file://` 直接打开也能跑。

## 三、运行方法

### 1. 拿到代码

```bash
git clone https://github.com/wqwabc/102402137-102402139.git
```

或在 GitHub 页面 `Code → Download ZIP` 后解压。

### 2. 打开网页（无需任何环境）

1. 保持目录结构不变；
2. **用谷歌浏览器 Chrome** 双击打开根目录下的 `index.html`；
   - 项目按 `file://` 协议即可正常工作（没用 fetch / ES module）；
   - 若浏览器限制较严，也可用 VS Code 的 Live Server 以 `http://` 打开，效果一致。
3. 首次打开会自动写入 **6 条演示数据**（其中 3 条带示例图片），首页立刻有内容。

> 统一用 Chrome，避免不同浏览器在日期控件、`localStorage` 上的行为差异。

### 3. 使用说明

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| ① 发布 | 首页点「我丢了东西 / 我捡到东西」→ 填必填项 → 立即发布 | 发布成功页，显示编号与摘要；若有相关信息会提示“智能配对” |
| ② 校验 | 不填必填项直接发布 | 顶部出现红色错误清单，不白屏 |
| ③ 搜索 | 输入「雨伞」「校园卡」 | 列表实时过滤，命中字黄色高亮；搜不到有空状态提示 |
| ④ 筛选 | 点分类/地点胶囊、寻物招领 tab、最新/最热 | 列表内容随之变化 |
| ⑤ 悬浮预览 | 鼠标停在任意卡片上 | 旁边浮出简介、照片、地点时间 |
| ⑥ 详情 | 点任意卡片 | 进入详情：分类/地点/时间/编号/描述/照片 |
| ⑦ 联系 | 详情页点「联系失主/拾取人」 | 显示联系方式，点「复制」提示已复制 |
| ⑧ 状态 | 打开自己发的那条，底部「发布者管理」 | 可标记已找到/已归还、编辑、删除 |
| ⑨ 我的 | 底部导航进「我的」 | 个人资料卡 + 我的发布；点铅笔可改昵称/头像/学院/校区/联系方式 |

## 四、功能清单

### 4.1 核心功能

| 要求 | 实现位置 |
| --- | --- |
| 发布寻物 / 招领 | `publish.html` + `Store.add`，含类型、名称、分类、图标、地点、时间、描述、照片、联系方式 |
| 集中浏览 | `index.html` 卡片列表，含类型/状态徽标、图标、地点、时间 |
| 关键词搜索 | `Store.query()`，标题+描述+地点匹配，命中高亮 |
| 查看详情与联系方式 | `detail.html`，联系方式默认隐藏、点击查看、一键复制 |
| 更新状态 | `Store.updateStatus`，发布者标记已找到/已归还，可撤回；已解决自动灰化沉底 |
| 减少重复询问 | 状态徽标 + 已解决沉底，一眼看出哪些已了结 |

### 4.2 附加特点

1. **一键复制联系方式**：电话/QQ/微信均可一键复制。
2. **地点筛选 + 最新/最热排序 + 分页**：按校园地点筛选，按浏览量/时间排序。
3. **智能配对提醒**：发布成功时自动找「相反类型 + 同分类 + 标题有 2 字重合 + 仍在进行中」的信息推给用户，让失主和拾主主动碰上头。
4. **悬浮预览**：鼠标停在列表卡片上即浮出简介、照片、地点时间，不必点进详情。
5. **编辑已发布信息**：发布者可随时修改已发布内容（详情页「编辑信息」），改完保留原编号与状态。

## 五、单元测试

数据层 `js/store.js` 不依赖 DOM，可直接在 Node 里跑测试。

- 测试工具：Node 18+ 自带的 `node:test` + `node:assert/strict`，**零依赖**，不需要 `npm install`。
- 运行：

```bash
npm test
# 或直接
node --test test/store.test.js test/common.test.js test/flow.test.js test/pages.test.js
```

- 覆盖范围：
  - `store.test.js`：表单校验、增删改查、搜索/筛选/排序/分页、状态维护、智能配对、个人资料；
  - `common.test.js`：HTML 转义、关键词高亮、时间格式化、卡片渲染等纯函数；
  - `flow.test.js`：发布→浏览→详情→联系→更新状态→编辑/删除的主流程贯通；
  - `pages.test.js`：页面用到的 id、脚本路径、页面互链、UTF-8 编码一致性检查；
  - `dom.flow.test.js`：可选，用 jsdom 真跑页面模拟点击，未装 jsdom 时自动跳过。
- 测试数据思路：先列字段的合法/非法/缺失三类取值，长度类取边界点（30/31 字等），每个分支真假都测，并对坏 JSON、空输入、不存在的 id 做兜底断言。

> 测试与网页运行完全解耦：不装 Node、不跑测试也不影响 Chrome 打开 `index.html`。

## 六、数据说明

| localStorage Key | 内容 |
| --- | --- |
| `campus_lost_found_items_v2` | 全部失物招领信息（数组） |
| `campus_profile_v1` | 当前用户昵称/头像/学院/校区/联系方式 |

- 所有数据都在浏览器本地，**不上传服务器**，符合“不做复杂后台”的范围；
- 数据保存在本机浏览器，换电脑/清缓存会清空；
- 上传的照片以 base64 压缩后存储，避免撑爆 localStorage。
